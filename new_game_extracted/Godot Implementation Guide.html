My Little Buddy — New UI Implementation Guide

Godot 4.6.2 · GDScript 2 · Authored from full codebase analysis + tileset render

Integration Approach

The /new ui/ folder contains 11 tilemap scenes (Map.tscn + TileMapLayer children). Each is a visual-only pixel-art frame: maroon panel, orange-bracket corners, cream title plaque, and baked button shapes — but no interactive Godot nodes, no text, no scripts.

The recommended integration keeps your existing Control-tree menus intact and uses the tilemap art purely as the backdrop:

Strategy: Instance each Map.tscn as a visual backdrop (Node2D, scaled up, nearest-filtered). Layer your real Button/Label nodes over it via a Control root anchored to the same panel region. Restyle the buttons to match the tileset palette (see style_pixel_button()) so they blend with the art. Then add JuicyButton to get the missing press animation and click sound.

Why not use the baked button shapes directly?

The baked button shapes are TileMapLayer pixels — you can't attach pressed signals or animate them. The cleanest path is: hide the baked button tiles layer (or keep it — they'll sit under real transparent Control buttons), and place properly-styled Button nodes anchored over each baked shape. The buttons look identical to the art and they can press, hover, and play sound.

Project Pixel Setup

The tilesets use 16×16 px tiles. To keep them crisp when scaled:

1

Go to Project → Project Settings → Rendering → Textures and set Default Texture Filter to Nearest. This stops bilinear blur on all pixel art.

2

When instancing a tilemap Map.tscn as a backdrop, set the parent Node2D scale to match your game resolution. At 16 px tiles and a 1024×576 viewport, scale ≈ 8 makes a 14×10-tile menu fill the screen (14×16×8 = 1792 px — bigger than viewport, so clamp; try scale 6–8 and tweak).

3

The tilemap's TileSet.tile_size = Vector2i(16,16) and texture_region_size = Vector2i(16,16). No changes needed — just import the tileset.png with Filter = Nearest in the Import dock.

Step 1 — Sfx Autoload

Create res://scripts/Sfx.gd and add it as an autoload singleton named Sfx (Project → Project Settings → AutoLoad). Drop a short click WAV at res://assets/sfx/click.wav (16-bit, mono, <100ms — any pixel-blip sound works).

# Sfx.gd  — AutoLoad singleton
extends Node

var _player : AudioStreamPlayer
var _click  : AudioStream = null

func _ready() -> void:
    _player = AudioStreamPlayer.new()
    _player.bus = "Master"
    add_child(_player)
    var p := "res://assets/sfx/click.wav"
    if ResourceLoader.exists(p):
        _click = load(p)

func click(pitch : float = 1.0) -> void:
    if _click == null: return
    _player.stream = _click
    _player.pitch_scale = randf_range(0.94, 1.08) * pitch
    _player.volume_db = -6.0
    _player.play()

Step 2 — JuicyButton Script

A drop-in script for any Button. Gives hover scale-up, pixel press-down (squash), and click sound. Works inside VBoxContainers because it uses scale (which containers don't touch) rather than position.

# JuicyButton.gd
# Usage: set this as a Button's script, OR call _juice(btn) from code.
class_name JuicyButton
extends Button

@export var press_squash  : float = 0.88   # Y scale on press
@export var hover_scale   : float = 1.05   # uniform scale on hover
@export var anim_secs     : float = 0.07
@export var play_sound    : bool  = true

var _tw : Tween

func _ready() -> void:
    _centre_pivot()
    resized.connect(_centre_pivot)
    mouse_entered.connect(_hover)
    mouse_exited.connect(_unhover)
    button_down.connect(_down)
    button_up.connect(_up)

func _centre_pivot() -> void:
    pivot_offset = size * 0.5

func _go(target_scale : Vector2, trans := Tween.TRANS_BACK, ease := Tween.EASE_OUT) -> void:
    if _tw: _tw.kill()
    _tw = create_tween().set_trans(trans).set_ease(ease)
    _tw.tween_property(self, "scale", target_scale, anim_secs)

func _hover()   -> void: if not disabled: _go(Vector2.ONE * hover_scale)
func _unhover() -> void: _go(Vector2.ONE, Tween.TRANS_EXPO)
func _down()    -> void:
    if play_sound: Sfx.click()
    _go(Vector2(1.03, press_squash), Tween.TRANS_QUAD, Tween.EASE_IN)
func _up()      -> void: _go(Vector2.ONE * (hover_scale if is_hovered() else 1.0))

Step 3 — Wire it into UITheme (one change, all menus)

Your UITheme.gd already walks every node via _style_children_recursive. Add the juice call inside the node is Button branch so every existing and future menu gets it for free:

# In UITheme.gd — _style_children_recursive()
elif node is Button:
    style_button(node, _auto_button_color(node))
    _juice_button(node)   # ← ADD THIS LINE

# Add this static function to UITheme.gd:
static func _juice_button(btn : Button) -> void:
    if btn.has_meta("juiced"): return
    btn.set_meta("juiced", true)
    btn.call_deferred("_do_juice")   # deferred so size is known

# Helper that runs after layout so pivot is correct:
static func _do_juice_on(btn : Button) -> void:
    btn.pivot_offset = btn.size * 0.5
    btn.resized.connect(func(): btn.pivot_offset = btn.size * 0.5)
    btn.mouse_entered.connect(func():
        if btn.disabled: return
        var tw := btn.create_tween().set_trans(Tween.TRANS_BACK).set_ease(Tween.EASE_OUT)
        tw.tween_property(btn, "scale", Vector2.ONE * 1.05, 0.10))
    btn.mouse_exited.connect(func():
        var tw := btn.create_tween()
        tw.tween_property(btn, "scale", Vector2.ONE, 0.08))
    btn.button_down.connect(func():
        Sfx.click()
        var tw := btn.create_tween().set_trans(Tween.TRANS_QUAD).set_ease(Tween.EASE_IN)
        tw.tween_property(btn, "scale", Vector2(1.03, 0.88), 0.06))
    btn.button_up.connect(func():
        var tw := btn.create_tween().set_trans(Tween.TRANS_BACK).set_ease(Tween.EASE_OUT)
        tw.tween_property(btn, "scale", Vector2.ONE, 0.10))
Note: In the _juice_button static func, calling btn.call_deferred("_do_juice") won't work because _do_juice doesn't exist on Button. Instead call _do_juice_on(btn) wrapped in a deferred lambda: btn.call_deferred(func(): UITheme._do_juice_on(btn)) — or simply call it directly if you know the layout has resolved.

Step 4 — style_pixel_button() — New Palette Styling

Replace calls to UITheme.style_button(btn, color) with this new function wherever you want the full new-UI pixel look. Or call it from the UITheme hook above. The trick is a thick bottom border that gets thinner on press, making the button visually sink.

# Add to UITheme.gd
const CLR_INK      := Color("#493333")
const CLR_TAN      := Color("#e5b67f")
const CLR_TAN_HI   := Color("#f0cb97")
const CLR_TAN_DRK  := Color("#c7895d")
const CLR_GRAY     := Color("#c6b09b")
const CLR_GRAY_DRK := Color("#8a7868")

static func style_pixel_button(btn : Button, secondary : bool = false) -> void:
    var f := get_pixel_font()
    if f: btn.add_theme_font_override("font", f)
    btn.add_theme_color_override("font_color",         CLR_INK)
    btn.add_theme_color_override("font_hover_color",   CLR_INK)
    btn.add_theme_color_override("font_pressed_color", CLR_INK)

    var fill     := CLR_GRAY    if secondary else CLR_TAN
    var fill_hi  := CLR_GRAY    if secondary else CLR_TAN_HI
    var fill_drk := CLR_GRAY_DRK if secondary else CLR_TAN_DRK

    btn.add_theme_stylebox_override("normal",   _pxsb(fill,     fill_drk, 8))
    btn.add_theme_stylebox_override("hover",    _pxsb(fill_hi,  fill_drk, 8))
    btn.add_theme_stylebox_override("pressed",  _pxsb(fill.darkened(0.06), fill_drk, 2))
    btn.add_theme_stylebox_override("disabled", _pxsb(fill.darkened(0.3), fill_drk, 0))

static func _pxsb(fill : Color, shadow : Color, depth : int) -> StyleBoxFlat:
    var sb := StyleBoxFlat.new()
    sb.bg_color         = fill
    sb.border_color     = CLR_INK
    sb.border_width_top    = 3
    sb.border_width_left   = 3
    sb.border_width_right  = 3
    sb.border_width_bottom = 3 + depth          # thick bottom = 3-D base
    sb.anti_aliasing       = false             # crisp pixel edges
    sb.set_corner_radius_all(0)                  # sharp = pixel art
    sb.content_margin_left   = 18
    sb.content_margin_right  = 18
    sb.content_margin_top    = 12
    sb.content_margin_bottom = 12 + (8 - depth) # shrinks on press = sinks
    return sb

Tilemap Background Integration

Each menu folder contains: Map.tscn (root composer), 2–4 Layer_*.tscn files (TileMapLayers), tileset.tres and tileset.png. The draw order is: highest filename-suffix = bottom-most layer (e.g. Layer_0_2 drawn first, Layer_2_0 on top).

Node structure for each menu

# Every menu adopts this pattern:
CanvasLayer           # your existing CanvasLayer root
└─ Control "Root"      # anchor_preset = FULL_RECT
   ├─ Node2D "Backdrop"  # ← NEW: instance of Map.tscn
   │    scale = Vector2(8, 8)   # scale 16px tiles to fill viewport
   │    position = Vector2(-panelOffsetX, -panelOffsetY)
   └─ VBoxContainer     # your existing content (labels, buttons)
        anchors_preset = FULL_RECT  # or anchored to panel region
Tip: After instancing Map.tscn, open it and toggle off any pure-button TileMapLayers (the ones whose layer name ends in _0 on top, e.g. Buttons_1 in Dog Chooser or Layer_1_0 in Opening). Real Button nodes styled with style_pixel_button() will replace them and look identical — but they animate and emit signals.

Coordinate alignment

The tilemap's content starts at tile (0,0). With scale=8, tile (0,0) = pixel (0,0). The Opening Menu's title plaque spans tiles (1,1)–(12,2), which at scale=8 = pixels (128,128)–(960,160). Position your title Label to match. Each menu's exact tile regions are visible in the interactive prototype (open it, hover elements to see alignment).

Character Creator / Player Editor (CharacterCustomize.gd)

Unlike the 11 tilemap menus, the Character Creator is built 100% in code — _build_ui() constructs every node with StyleBoxFlat overrides and a blue-checker shader background. There is no Map.tscn for it in /new ui/, so re-skinning it means swapping the colours and styleboxes in the script to match the new maroon pixel-art theme. No layout changes needed — just colours, borders, and the background.

What changes: the blue checker background → maroon; gray/blue tabs → tan/orange; tile panels → cream & deep-maroon; the gray bottom bar → cream with an ink border. The 4-direction preview, carousel, grid, name field, and checkboxes all keep their exact positions and behaviour.

Step A — Maroon background (replace the blue checker shader)

In _create_checker_bg(), swap the two shader colours to the new maroon pair (keeps the subtle checker texture):

# _create_checker_bg() — change the two uniforms
uniform vec4 color1 : source_color = vec4(0.718, 0.357, 0.373, 1.0); # #b75b5f maroon
uniform vec4 color2 : source_color = vec4(0.612, 0.263, 0.318, 1.0); # #9c4351 deep

Step B — Title colour to cream

# In _build_ui(), the title Label:
title.add_theme_color_override("font_color", Color("#ffd7a8"))    # cream
title.add_theme_color_override("font_shadow_color", Color("#9c4351")) # maroon-deep drop

Step C — Tab buttons → tan / orange-active

In _create_tab_button(), replace the stylebox colours and square the corners:

# normal (inactive)
sb.bg_color     = Color("#8a7868")   # gray-dark
sb.border_color = Color("#493333")   # ink
sb.set_corner_radius_all(0)                # sharp pixel corners
# hover
sb_hover.bg_color = Color("#9c8975")
# active (selected tab)
sb_active.bg_color     = Color("#ffa34d")  # orange
sb_active.border_color = Color("#493333")  # ink
# set active tab's font to ink so it reads on orange:
sb_active.set_corner_radius_all(0)

Step D — Grid tiles → cream / deep-maroon, gold selection

In _build_tile(), swap the selected/unselected colours:

sb.bg_color     = Color("#493333") if is_selected else Color("#c6b09b")
sb.border_color = Color("#ffd071") if is_selected else Color("#493333")
sb.set_corner_radius_all(0)
# put a deep-maroon PanelContainer (#9c4351) behind the GridContainer
# so the grid reads as a framed tray like the prototype.

Step E — Bottom bar → cream with ink border

# _create_bottom_bar() — the panel StyleBoxFlat:
sb.bg_color         = Color("#ffd7a8")  # cream
sb.border_color     = Color("#493333")  # ink
sb.border_width_top = 6
# NAME label + checkbox text already dark — reads fine on cream

Step F — Buttons use the new pixel style + juice

The Character Creator builds buttons via its own _create_styled_button(). Two options:

1

Quick: change the bg_color args passed in — BACK → #c6b09b (gray), RANDOMIZE → #ffa34d (orange), CONTINUE → #4caf50 (green). Inside _create_styled_button() set sb.set_corner_radius_all(0) and bump sb.border_width_bottom = 6 to fake the pixel base.

2

Best: after building each button call UITheme._do_juice_on(btn) (from Step 3) so the direction arrows, BACK, RANDOMIZE, CONTINUE — and every grid tile — get hover-scale + press-squash + Sfx.click(). For tiles, call it inside _build_tile() right before return btn.

Selected-tile label: the "%s %02d" footer (e.g. "BODY 01") already uses the pixel font + white text — on the new dark-selected tile it stays readable. No change needed.
